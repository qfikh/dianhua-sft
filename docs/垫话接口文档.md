# 垫话生成接口文档

## 概述

本接口用于汽车客服场景下的"垫话"自动生成。垫话是指在回答客户问题之前，先进行一次语言承接，如"好的。"、"我明白您的意思。"等，以体现专业礼貌、平稳过渡到正式解答。

---

## 接口信息

| 项目 | 说明 |
|------|------|
| **接口地址** | `{base_url}/v1/chat/completions` |
| **请求方式** | POST |
| **数据格式** | JSON |
| **默认端口** | 5010 |

---

## 请求参数

### Headers

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| Content-Type | string | 是 | 固定值：`application/json` |

### Body 参数

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| model | string | 是 | - | 模型名称，固定为 `qwen3-4b_0409_sft` |
| messages | array | 是 | - | 对话消息列表 |
| max_tokens | integer | 否 | 50 | 最大生成token数 |
| temperature | float | 否 | 0.1 | 温度参数，控制随机性 |
| top_p | float | 否 | 0.9 | 核采样参数 |
| stream | boolean | 否 | false | 是否流式输出 |
| extra_body | object | 否 | - | 扩展参数 |

#### messages 结构

```json
[
  {
    "role": "system",
    "content": "系统提示词（见下方说明）"
  },
  {
    "role": "user",
    "content": "对话历史"
  }
]
```

#### extra_body 结构

```json
{
  "chat_template_kwargs": {
    "enable_thinking": false
  }
}
```

## 请求示例

### cURL 示例

```bash
curl -X POST "http://192.168.86.3:5010/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3-4b_0409_sft",
    "messages": [
      {
        "role": "system",
        "content": "以下是汽车客服和客户之间的对话数据，你是一个话术指导老师..."
      },
      {
        "role": "user",
        "content": "客服：您好，我是一汽大众的官方客服，看到您近期有在app上关注过我们的车，是吗？\n客户：诶，是的\n客服：嗯~请问您是在关注我们的哪款车型呢？\n客户：最新的车\n客服："
      }
    ],
    "max_tokens": 50,
    "temperature": 0.1,
    "top_p": 0.9,
    "stream": false,
    "extra_body": {
      "chat_template_kwargs": {
        "enable_thinking": false
      }
    }
  }'
```

### Python 示例

```python
import requests

def generate_cushion(conversation_history: str, base_url: str = "http://localhost:5010") -> str:
    """生成垫话

    Args:
        conversation_history: 对话历史，格式如："客服：xxx\n客户：xxx\n客服："
        base_url: 服务地址

    Returns:
        生成的垫话内容，如"我明白了。"或"无"
    """
    system_prompt = """以下是汽车客服和客户之间的对话数据，你是一个话术指导老师。现在需要你进行一次"垫话"。
"垫话"的意思是：在回答客户问题之前，先进行一次语言承接...（完整提示词见附录）"""

    payload = {
        "model": "qwen3-4b_0409_sft",
        "messages": [
            {"role": "system", "content": system_prompt + "\n/no_think"},
            {"role": "user", "content": conversation_history}
        ],
        "max_tokens": 50,
        "temperature": 0.1,
        "top_p": 0.9,
        "stream": False,
        "extra_body": {
            "chat_template_kwargs": {
                "enable_thinking": False
            }
        }
    }

    response = requests.post(
        f"{base_url}/v1/chat/completions",
        json=payload,
        timeout=30
    )

    if response.status_code == 200:
        result = response.json()
        return result["choices"][0]["message"]["content"]
    return "无"
```

## 输出说明

### 正常垫话输出

生成的垫话为 1-10 字的短句，以句号结尾，例如：

| 示例输出 | 适用场景 |
|----------|----------|
| 嗯。 | 常规承接 |
| 嗯嗯。 | 轻度共情 |
| 我明白了。 | 表达理解 |
| 了解您的诉求了。 | 正式场合 |
| 我理解您的情况。 | 客户有诉求时 |

### 特殊输出

当以下情况时，接口返回 `"无"`：

1. 客户只说了语气词，如"嗯"、"啊"等
2. 客户只说"对对对"、"好的"、"知道了"
3. 无有效内容可承接
4. 只有零散词语，没有完整意思表达
5. 客户语句不完整、卡顿、只说一半

## 对话历史格式

### 输入格式

对话历史应采用以下格式：

```
客服：[客服说话内容]
客户：[客户说话内容]
客服：[客服说话内容]
客户：[客户说话内容]
客服：
```

**注意**：
- 最后一行必须是 `客服：`，用于提示模型在此处生成垫话
- 建议保留最近 4 句对话作为上下文
- 角色标签支持 `客服：`/`客户：` 或 `Service：`/`Client：`（会自动转换）

## 垫话生成规则

### 基本要求

1. **简洁短句**：控制在 1-10 字，不拖沓
2. **灵活多变**：根据不同场景输出不同垫话，避免单一
3. **语气词限制**：可输出"嗯。"、"嗯嗯。"等，但不能输出"哦"
4. **精准承接**：贴合客户上一句表述（疑问、否认、迷茫、急躁等）
5. **专业中性**：不随意夸张附和，保持职业中立性
6. **轻度共情**：客户疑惑、急躁时带轻微安抚感

### 禁止事项

- ❌ 严禁带有观点性答复："能"/"不能"/"可以"/"不可以"/"是的"/"不行"
- ❌ 严禁输出疑问句或带问号
- ❌ 严禁重复或复述客户原话
- ❌ 严禁直接回应问题本身

## 附录：完整系统提示词

```
以下是汽车客服和客户之间的对话数据，你是一个话术指导老师。现在需要你进行一次"垫话"。
"垫话"的意思是：在回答客户问题之前，先进行一次语言承接，比如"好的。"、"我明白您的意思。"、"嗯。"、"嗯嗯。"、"我明白了。"、"我知道了。"、"晓得了。"。

垫话的基本要求如下：
坐席的垫话核心作用是承接客户话语、体现专业礼貌、平稳过渡到正式解答，区别于日常闲聊，需贴合服务岗位的规范与调性，标准如下：
（1）简洁短句，不拖沓
控制在 1-10 字，不占用沟通时长，不打断对话节奏，避免长篇铺垫。
（2）要灵活多变，根据不同的场景输出不同的垫话，不要只输出一种说法...
（3）可以输出语气词，如"嗯。"、"嗯嗯。"、"嗯好。"等，但不能输出"哦"。
（4）精准承接，不脱节
贴合客户上一句的表述（疑问、否认、迷茫、急躁等），不凭空说垫话。
（5）专业中性，不情绪化
不随意夸张附和、不情绪化吐槽，保持坐席的职业中立性。
（6）轻度共情，适配情绪
客户疑惑、急躁时，垫话带轻微安抚感；客户正常沟通时，保持常规承接即可。
（7）不能带有观点，严禁对客户问题做出 "能"/"不能"/"可以"/"不可以"/"是的"/"不行"/"不对" 等任何明确答复性表述...
（8）垫话必须带标点，每条结尾必须加句号...
（9）输出垫话严禁重复或复述客户最后一句原话...

场景要求：
（1）如果客户只是说了语气词，比如"嗯"、"啊"等，要输出"无"。
（2）如只说 "对对对""好的""知道了"，无需额外承接垫话，要输出"无"。
（3）无有效内容可承接时，要输出"无"。
（4）只有零散词语，没有完整意思表达，不适合垫话，要输出"无"。
（5）如果客户没有说完话，如语句不完整、卡顿、只说一半、还在组织语言，没有形成完整问题或诉求，要输出"无"。
```
